title: 搜索空间与回溯
---
寻找满足条件的选择组合的问题，可以看作一棵叫作**搜索空间**的树。根是什么都还没选的状态，每条边是一个选择，每片叶子是做完所有选择的候选。这棵树增长得很快。对 n 个商品逐个决定放不放，叶子有 2ⁿ 个；把 n 个东西排成一排，有 n! 个。

**回溯**是一种沿着这棵树深度优先向下走的搜索：一旦部分选择已经违反条件，就丢弃它下面的整个分支（剪枝）。

## 在不可变状态下，撤销是免费的

命令式代码会修改棋盘、递归、回来后再撤销修改。漏掉撤销，下一个分支就会被污染。使用不可变值时，只需构造新状态传给递归调用。调用方的状态保持不变，所以调用结束后直接从原状态尝试下一个选择即可。没有撤销代码，也就没有撤销的 bug。

## 结果用什么返回

同样的搜索，根据所问的问题不同，合并各分支结果的方法也不同。

- **解的个数**：返回 `Int`，把各分支得到的数加起来。
- **所有解**：返回 `List`，把各分支的结果拼接起来。失败就是空列表。
- **一个解**：返回 `Result`，前一个分支是 `Ok` 就停下，是 `Error` 就尝试下一个分支。

下面两个函数处理的是：在商品价格列表中找出和恰好等于 `budget` 的组合。假设价格都是正数。对每个商品，都分“放入”和“不放入”两路往下走。

```gleam
pub fn count_combinations(prices: List(Int), budget: Int) -> Int {
  case budget, prices {
    0, _ -> 1
    _, _ if budget < 0 -> 0
    _, [] -> 0
    _, [price, ..rest] ->
      count_combinations(rest, budget - price)
      + count_combinations(rest, budget)
  }
}

pub fn find_combination(
  prices: List(Int),
  budget: Int,
) -> Result(List(Int), Nil) {
  case budget, prices {
    0, _ -> Ok([])
    _, _ if budget < 0 -> Error(Nil)
    _, [] -> Error(Nil)
    _, [price, ..rest] ->
      case find_combination(rest, budget - price) {
        Ok(chosen) -> Ok([price, ..chosen])
        Error(Nil) -> find_combination(rest, budget)
      }
  }
}
```

例如 `count_combinations([2, 3, 5], 5)` 有 `[2, 3]` 和 `[5]` 两种，所以结果是 2。基本情况的顺序是有含义的。剩余预算为 0，说明无论还剩哪些商品，一个组合都已经完成；预算变成负数，说明这个分支不必再看下去。

## 剪枝越早越好

如果在叶子处一次性检查条件，就连要丢弃的候选也会一直构造到底。如果每增加一个选择就检查一次，错误的部分选择下面的分支就会被整个跳过。最坏复杂度不变，但实际访问的节点数会大幅减少。在上面的例子里，预算一变成负数，就不再看它下面的部分。

如果同一个状态（这里是“剩余商品的位置和剩余预算”）在多个分支中反复出现，就可以加上备忘，改成动态规划。

## 最短路径要用广度优先

深度优先搜索能找到某条路径，但不能保证它最短。在所有边代价相同的图或网格中求最短距离，要用**广度优先搜索（BFS）**。它先看完距起点为 1 的所有格子，再看距离为 2 的格子，这样一圈圈扩散，所以第一次到达目的地时的距离就是最短距离。

- 需要**队列**。往单个列表末尾追加，每次放入都是 O(n)，所以要用两个列表实现的队列，或者由“当前距离的格子列表”一次性构造出“下一距离的格子列表”。
- 需要**已访问集合**。没有它，同一个格子会被放入多次，在有环的图中搜索永远不会结束。要在把格子**放入**队列时就标记为已访问，同一个格子才不会多次进入队列。

## 这个概念用在哪里

- 拼接碎片、摆放棋子这类依次累积选择的组合搜索。
- 迷宫和网格中的最短距离（广度优先搜索）。
- 把反复出现的状态记入备忘、改成动态规划的出发点。
