title: 动态规划：每个子问题只解一次
---
如果递归拆分问题后，同一个子问题沿着不同路径反复出现，就把第一次解出的答案存起来再复用。这就是动态规划。满足以下两个条件时使用它。

- **最优子结构**：大问题的答案可以由小问题的答案构造出来。
- **重叠子问题**：同一个小问题会被多次用到。

## 重叠让代价爆炸

把斐波那契数 `fib(n) = fib(n - 1) + fib(n - 2)` 直接写成递归，`fib(n - 2)` 会在两个分支里都被计算，更下面也一样。调用次数随 n 呈指数增长（大约 1.6ⁿ）。可是不同的子问题只有 `fib(0)` 到 `fib(n)` 这 n + 1 个。每个只解一次，就是 O(n)。

## 设计步骤

1. **状态**：用什么来区分子问题？比如列表中的位置、剩余金额、两个字符串前缀长度组成的对。如果状态里漏掉了影响答案的信息，不同的问题就会被存到同一个格子里，答案就会出错。
2. **递推式**：用更小状态的答案写出一个状态的答案。
3. **基本情况**：无法再缩小的状态的答案，通常是规模为 0 的情况，比如“凑出 0 元的方法数”“到空字符串的距离”。
4. **计算顺序**：计算某个状态时，它需要的更小状态必须已经准备好。
5. **答案的位置**：原问题对应哪个状态？

总代价大致是（状态数）×（计算一个状态的代价）。如果表用 `Dict` 存，每次查找还要多出大约 O(log n)。

## 自顶向下：把备忘表一起传递

不可变语言没有全局缓存，所以要把备忘表作为参数接收，并把更新后的表和结果一起返回。

```gleam
import gleam/dict.{type Dict}

pub fn fib_memo(n: Int, memo: Dict(Int, Int)) -> #(Int, Dict(Int, Int)) {
  case n <= 1 {
    True -> #(n, memo)
    False ->
      case dict.get(memo, n) {
        Ok(value) -> #(value, memo)
        Error(Nil) -> {
          let #(a, memo) = fib_memo(n - 1, memo)
          let #(b, memo) = fib_memo(n - 2, memo)
          let value = a + b
          #(value, dict.insert(memo, n, value))
        }
      }
  }
}
```

关键在于把第一次调用**返回**的表传给第二次调用。如果把最初拿到的表原样传给两次调用，第一次调用填好的格子就被丢掉了，代码里明明有备忘表，却仍然要花指数时间。像上面这样用同一个名字 `memo` 重新绑定，就不会误用旧表。

## 自底向上：只带着需要的部分

从小状态开始依次填写，计算顺序自然就对了。斐波那契只需要前两个值，所以用两个累加器代替整张表就够了。

```gleam
pub fn fib(n: Int) -> Int {
  case n <= 0 {
    True -> 0
    False -> fib_loop(1, n, 0, 1)
  }
}

// previous = fib(i - 1), current = fib(i)
fn fib_loop(i: Int, n: Int, previous: Int, current: Int) -> Int {
  case i == n {
    True -> current
    False -> fib_loop(i + 1, n, current, previous + current)
  }
}
```

状态是二维时也用同样的思路。如果每一行只依赖紧挨着的上一行，就不必保存整张表，只把上一行作为列表带着走，用它构造下一行。访问列表的第 i 个元素是 O(i)，所以构造一行时不要按下标查找，而是与上一行并排遍历。

## 贪心行不通的情况

当“每次都选看起来最好的”不能保证全局最优时，就需要动态规划。用 1 元、3 元、4 元硬币凑 6 元，先选大硬币得到 4 + 1 + 1，共 3 枚，而最优解是 3 + 3，只要 2 枚。必须用子问题的答案比较所有选择。

## 这个概念用在哪里

- 求最少个数、最大价值、方案数、两个字符串之间距离的问题。
- 回溯搜索中同一个状态反复出现时。以状态为键加上备忘表，就成了动态规划。
