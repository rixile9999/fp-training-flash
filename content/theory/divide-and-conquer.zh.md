title: 分治与递推式
---
分治分三步解决问题。

1. **分解**：把输入拆成同类的更小问题。
2. **解决**：递归地解决小问题。
3. **合并**：用小问题的答案构造原问题的答案。

此外还必须有不再拆分、直接给出答案的**基本情况**。

## 正确性：相信小问题的答案是对的

这里适用与结构递归相同的归纳推理。假设递归调用在更小的输入上给出正确答案，然后只需检查合并步骤是否正确。要让这个推理成立，需要两个条件。

- 每次递归调用的输入都必须**严格**更小。
- 基本情况必须覆盖**所有**无法再拆分的输入。

归并排序中常被忽略的是第二个条件。把只有一个元素的列表对半分，会得到 `[]` 和 `[x]`，而 `[x]` 与原输入大小相同。如果基本情况只有 `[]`，就会用同一个输入无限递归下去。所以 `[]` 和 `[x]` 都要作为基本情况。

## 例子：求幂

计算 `base` 的 `exponent` 次方时，不做 `exponent` 次乘法，而是把指数对半分。假设 `exponent` 大于等于 0。

```gleam
pub fn power(base: Int, exponent: Int) -> Int {
  case exponent {
    0 -> 1
    _ -> {
      let half = power(base, exponent / 2)
      case exponent % 2 {
        0 -> half * half
        _ -> half * half * base
      }
    }
  }
}
```

设指数为 n。递归调用只有一次，n 每次减半，所以乘法次数是 O(log n)。如果不用 `let` 接住 `half`，而是写成 `power(base, exponent / 2) * power(base, exponent / 2)`，结果相同，但调用会分成两路，乘法次数变成 O(n)。拆分得到的好处，全都浪费在把同一个子问题解两遍上了。

## 代价：用递推式来算

把规模为 n 的问题的代价 T(n) 写成“小问题的代价 + 分解与合并的代价”。

| 递推式 | 例子 | 结果 |
|---|---|---|
| T(n) = T(n/2) + O(1) | 求幂、在平衡树中只往一侧向下走 | O(log n) |
| T(n) = 2T(n/2) + O(1) | 访问平衡树的所有节点 | O(n) |
| T(n) = 2T(n/2) + O(n) | 归并排序 | O(n log n) |
| T(n) = T(n-1) + O(n) | 每次拆成 1 个元素和其余部分 | O(n²) |

把归并排序画成递归树就能看出原因。规模每次减半，所以深度是 log₂ n；每一层合并的元素数加起来是 n。每层 O(n)，共 log n 层，所以是 O(n log n)。

把列表对半分需要数长度并复制前半部分，代价是 O(n)。合并本来就是 O(n)，所以整体的阶不变。反过来，如果拆分偏向一侧，深度就会变成 n，代价退化为 O(n²)。按有序顺序插入值的二叉搜索树变得像列表一样长，也是同一种现象。

## 合并步骤里藏着需求

归并排序的合并步骤会比较两个有序列表的首元素，先输出较小的那个。两个值相等时，先输出左边列表的元素，才能保持相同键元素的原有顺序（稳定排序）。比较是用 `<` 还是 `<=`，决定了这个性质。

## 这个概念用在哪里

- 排序（归并排序）、二叉搜索树的插入与查找等拆分输入来求解的算法。
- 各种树形数据结构。左右子树就是天然的拆分。
- 如果拆出来的子问题互相重叠，单靠分治会重复做同样的工作。这时就该转向动态规划。
