분할 정복은 문제를 세 단계로 푼다.

1. **나누기**: 입력을 같은 종류의 더 작은 문제로 쪼갠다.
2. **정복하기**: 작은 문제를 재귀로 푼다.
3. **합치기**: 작은 문제의 답으로 원래 문제의 답을 만든다.

그리고 더 나누지 않고 바로 답하는 **기저 사례**가 있어야 한다.

## 정확성: 작은 문제의 답은 맞다고 믿는다

구조적 재귀와 같은 귀납 논리가 적용된다. 재귀 호출이 더 작은 입력에서 옳은 답을 준다고 가정하고, 합치기 단계가 옳은지만 확인하면 된다. 이 논리가 성립하려면 두 조건이 필요하다.

- 모든 재귀 호출의 입력이 **엄격히** 작아야 한다.
- 기저 사례가 더 나눌 수 없는 입력을 **모두** 덮어야 한다.

병합 정렬에서 자주 놓치는 부분이 두 번째 조건이다. 원소가 하나인 목록을 반으로 나누면 `[]`와 `[x]`가 되고, `[x]`는 원래 입력과 크기가 같다. 기저 사례가 `[]`뿐이면 같은 입력으로 끝없이 재귀한다. 그래서 `[]`와 `[x]`를 모두 기저 사례로 둔다.

## 예: 거듭제곱

`base`의 `exponent`제곱을 곱셈 `exponent`번 대신 지수를 반으로 나눠 계산한다. `exponent`는 0 이상이라고 가정한다.

```gleam
pub fn power(base: Int, exponent: Int) -> Int {
  case exponent {
    0 -> 1
    _ -> {
      let half = power(base, exponent / 2)
      case exponent % 2 {
        0 -> half * half
        _ -> half * half * base
      }
    }
  }
}
```

지수를 n이라 하면, 재귀 호출은 한 번뿐이고 n이 매번 절반이 되므로 곱셈은 O(log n)번이다. `half`를 `let`으로 받지 않고 `power(base, exponent / 2) * power(base, exponent / 2)`라고 쓰면 결과는 같지만 호출이 두 갈래로 늘어나 O(n)번이 된다. 나눠서 얻은 이득이 같은 부분 문제를 두 번 푸는 데 전부 사라진다.

## 비용: 점화식으로 센다

크기 n인 문제의 비용 T(n)을 "작은 문제들의 비용 + 나누기와 합치기의 비용"으로 적는다.

| 점화식 | 예 | 결과 |
|---|---|---|
| T(n) = T(n/2) + O(1) | 거듭제곱, 균형 트리에서 한쪽으로만 내려가기 | O(log n) |
| T(n) = 2T(n/2) + O(1) | 균형 트리의 모든 노드 방문 | O(n) |
| T(n) = 2T(n/2) + O(n) | 병합 정렬 | O(n log n) |
| T(n) = T(n-1) + O(n) | 매번 1개와 나머지로 나누는 분할 | O(n²) |

병합 정렬의 경우를 재귀 트리로 그려 보면 이유가 보인다. 크기가 절반씩 줄어드므로 깊이는 log₂ n이고, 각 층에서 합치는 원소 수를 모두 더하면 n이다. 층마다 O(n)씩 log n층이므로 O(n log n)이다.

목록을 반으로 나누는 데는 길이를 세고 앞 절반을 복사해야 하므로 O(n)이 든다. 합치기가 이미 O(n)이라 전체 차수는 변하지 않는다. 반대로 분할이 한쪽으로 치우치면 깊이가 n이 되어 O(n²)으로 떨어진다. 정렬된 순서로 값을 넣은 이진 탐색 트리가 목록처럼 길어지는 것도 같은 현상이다.

## 합치기에 요구사항이 숨어 있다

병합 정렬의 합치기는 정렬된 두 목록의 앞 원소를 비교해 작은 것을 먼저 내보낸다. 두 값이 같을 때 왼쪽 목록의 원소를 먼저 내보내야 같은 키를 가진 원소의 원래 순서가 유지된다(안정 정렬). 비교를 `<`로 쓰는지 `<=`로 쓰는지가 이 성질을 결정한다.

## 이 개념이 쓰이는 곳

- 정렬(병합 정렬), 이진 탐색 트리의 삽입과 조회처럼 입력을 나눠 푸는 알고리즘.
- 트리 자료구조 전반. 왼쪽과 오른쪽 부분 트리가 자연스러운 분할이다.
- 나눈 부분 문제들이 서로 겹치면 분할 정복만으로는 같은 일을 반복한다. 이때는 동적 계획법으로 넘어간다.
