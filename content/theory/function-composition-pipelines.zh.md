title: 函数组合与管道
---
有了函数 `f: a -> b` 和 `g: b -> c`，就能构造一个新函数 `a -> c`：先应用 `f`，再对结果应用 `g`。这就是**函数组合**，是把大变换表示为一连串小变换的最基本方法。

Gleam 的管道运算符 `|>` 让你按数据流动的顺序书写组合。`x |> f |> g` 等同于 `g(f(x))`。左边的值会作为右边函数的**第一个参数**传入；借助 `f(a, _)` 这样的函数捕获，也可以放到其他位置。

```gleam
import gleam/list
import gleam/string

pub fn normalize(tag: String) -> String {
  tag |> string.trim |> string.lowercase
}

pub fn parse_tags(raw: String) -> List(String) {
  raw
  |> string.split(",")
  |> list.map(normalize)
  |> list.filter(fn(tag) { tag != "" })
}
```

`parse_tags(" Gleam, FP ,,beam ")` 的结果是 `["gleam", "fp", "beam"]`。每一步只做一件事，光读名字就能看清整个流程。

## 为什么容易拆分

- **类型是黏合剂**：前一步的输出类型与后一步的输入类型对得上，才能接起来。步骤接错了，编译器会告诉你。
- **结合律**：组合无论怎样分组，结果都相同。所以把 `trim` 和 `lowercase` 两步打包命名为 `normalize`，或者再拆开，含义都一样。这正是把管道拆成可测试小块的依据。
- **每一步单独验证**：单独测试 `normalize`，对 `parse_tags` 只需确认各步骤连接正确。

本平台使用的 gleam_stdlib 1.0.5 中，`gleam/function` 模块只有 `identity`，没有组合函数。不过函数也是值，自己写一个很容易。

```gleam
pub fn compose(f: fn(a) -> b, g: fn(b) -> c) -> fn(a) -> c {
  fn(x) { g(f(x)) }
}
```

## 注意事项

- **顺序可能改变含义**：组合不满足交换律。如果先过滤空标签、再去除空白，像 `" "` 这样的标签会先通过过滤，然后变成空字符串留在结果里。先确认每一步假设了什么样的输入，再决定顺序。
- **一步只做一件事**：一步同时做解析和过滤，就很难命名，也很难复用。
- **效应放到最后**：如果在中间步骤里输出，合并或移动步骤时效应的次数和顺序就会改变。把纯粹的步骤串起来，效应在管道末尾执行一次。
- **数据作为第一个参数**：自己写的函数也把要处理的数据放在第一个参数，就能自然地接入管道。

## 这个概念用在哪里

- 字符串规范化、输入清理、报表生成等需要经过多个步骤的变换。
- 把长函数拆成有名字的步骤，再用管道重新连接的重构。
- 预测管道结果的题目中，依次追踪每一步的输入和输出。
