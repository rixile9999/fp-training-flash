title: 引用透明性：何时可以用值替换表达式
---
如果把某个表达式替换成它的值，程序的含义不变，那么这个表达式就是**引用透明**的。函数调用要做到引用透明，结果必须只依赖参数，而且调用除了产生结果之外，不能做任何从外部可以观察到的事（输出、写文件、发送消息、修改全局状态）。这样的函数叫作纯函数。

```gleam
pub fn line_total(price: Int, quantity: Int) -> Int {
  price * quantity
}

pub fn doubled() -> Int {
  let t = line_total(1200, 3)
  t + t
}
```

在 `doubled` 中，把 `t` 替换成 `line_total(1200, 3)`，或者反过来把 `line_total(1200, 3) + line_total(1200, 3)` 用 `let` 绑定，结果都同样是 7200。可以像数学里用相等的东西替换相等的东西那样处理代码（等式推理）。

## Gleam 不强制纯粹性

与 Haskell 不同，Gleam 不用类型追踪效应。任何函数都可以调用 `io.println`、向其他进程发送消息，或者通过外部函数读取当前时间。签名相同的函数，也未必都是纯的。

```gleam
import gleam/io

pub fn noisy_total(price: Int, quantity: Int) -> Int {
  io.println("计算中")
  price * quantity
}
```

在 `let t = noisy_total(1200, 3)` 之后计算 `t + t` 只输出一次，而 `noisy_total(1200, 3) + noisy_total(1200, 3)` 会输出两次。返回值相同，但可观察的行为不同，所以这个调用不是引用透明的。读取当前时间或随机数的函数，即使用相同参数调用，结果本身也会不同。因此在 Gleam 中，引用透明性不是靠编译器，而是靠**设计**来维护的性质。

## 为什么值得维护

- **提取函数是安全的**：把长函数的一部分抽出来命名，或者把重复的表达式绑定到一个变量上，含义都不会改变。这是通过函数分解进行重构的前提条件。
- **测试很简单**：给出输入，用 `should.equal` 比较结果就完了。不需要伪造对象，也不需要截获输出。
- **顺序和次数可以自由调整**：可以缓存结果、调整计算顺序，或者删掉不需要的调用。

常见的错误是在计算过程中打日志或直接读取当前时间，做出一个看似是计算函数、实际却无法测试的函数。这类值应该作为参数传入，要输出的内容则作为数据返回（参见“分离计算与效应”）。

## 这个概念用在哪里

- 把长函数拆成小函数时，先确认每一块是否是纯的。
- 设计“相同参数必须得到相同结果”的测试时。
- 在预测代码会输出什么的题目中，推敲带有效应的调用的次数和顺序时。
