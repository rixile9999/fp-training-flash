规则比基础题多了，但结构相同：拆分行、解析、用 fold 收集战绩、排序、输出各行。变化的只是每个步骤的**内部**，所以步骤之间的连接（`standings`）几乎可以原样复用。按步骤拆分函数，规则变化时需要修改的地方就会变少（理论笔记“函数组合与管道”）。

**解析。** 用嵌套的 `case` 依次检查：按 `;` 分割 → 按 `-` 分割 → 解析两个整数。只要有一处不对就是 `Error(Nil)`，所以 `3:0` 和空行会被自然地过滤掉。

**更新战绩。** 一场比赛给主队留下 `(主队进球, 客队进球)`，给客队留下 `(客队进球, 主队进球)`。写一个更新单支球队的 `add_game(stats, scored, conceded)`，只交换参数顺序调用两次，视角的转换就只在一处处理。胜平负也由 `int.compare(scored, conceded)` 的 `Gt/Eq/Lt` 决定，所以同一个函数对双方都适用。

**排序。** 依据有三个时，把 `order.break_tie` 连接两次。只有前一个依据为 `Eq` 时才看下一个，所以优先级与代码顺序完全一致。如果漏掉净胜球，积分相同的球队就只按名称排列，在测试中 `Incheon`（-1）和 `Busan`（-3）这种净胜球顺序与名称顺序不一致的情况下就会出错。

**输出。** 把加符号拆成 `signed(n)` 这样的小函数，就很容易单独检查 0 的情况。用 `n >= 0` 比较会得到 `+0`，只用 `int.to_string` 则正数会缺少 `+`。先确定边界值（0），再写条件。
