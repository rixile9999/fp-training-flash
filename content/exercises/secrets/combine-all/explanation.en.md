Combining a list of functions into one has the same shape as adding up a list of numbers. Just as the initial value of a sum is 0, the initial value of function composition is **the function that does nothing**, `fn(x) { x }` (the identity function). Chain the functions onto it one by one with `secret_combine`, and you get the single line `list.fold(fns, fn(x) { x }, secret_combine)`. Getting the identity function for an empty list also follows naturally from the initial value, with no separate branch.

The callback of `list.fold` takes its arguments in the order `fn(acc, f)`, and `secret_combine(acc, f)` applies "the functions combined so far first, the new function after". A common mistake is flipping the arguments to `secret_combine(f, acc)`, which applies the list **backwards**. Unlike addition, order matters in function composition.

For `secret_repeat`, rather than writing a new recursion, it's safer to turn the problem into "a list of `times` copies of the same function" and hand it to `secret_combine_all`. `list.repeat` returns an empty list when the count is 0 or less, so 0 and negative counts become the identity function automatically. When you write the recursion yourself, you often end up with an off-by-one base case such as returning `f` when `times <= 1`, or a recursion that never ends for negative counts.

The fact that a single small combining operation (`secret_combine`) and an identity element are all you need to combine a whole list is an example of the modularity discussed in the theory note "Higher-order functions and modularity".
