`secret_add(3)`은 숫자를 계산하지 않고 **"3을 더하는 일"을 값으로** 돌려줍니다. `fn(x) { x + secret }`의 본문은 바깥 함수의 인자 `secret`을 참조하는데, 익명 함수가 만들어질 때 그 값이 함께 붙잡혀(클로저) 나중에 호출될 때도 쓰입니다. 그래서 `secret_add(3)`과 `secret_add(10)`은 서로 다른 함수가 됩니다.

`secret_combine`은 함수 두 개를 받아 새 함수를 만드는 고차 함수입니다. `fn(x) { secret_function2(secret_function1(x)) }`는 수학의 합성 g ∘ f와 같습니다. 중첩 호출은 안쪽부터 실행되므로 `secret_function1`이 먼저 적용됩니다.

흔한 실수는 **순서**입니다.

- 빼기와 나누기는 교환 법칙이 성립하지 않으므로 `secret - x`, `secret / x`처럼 쓰면 틀립니다. 입력 `x`가 왼쪽에 옵니다.
- 합성 순서를 바꾸면 `secret_combine(secret_multiply(7), secret_divide(3))`처럼 우연히 같은 값이 나오는 경우도 있어 발견이 늦어집니다. `4에 3을 더하고 7로 나누기`(= 1)와 `4를 7로 나누고 3을 더하기`(= 3)처럼 순서에 민감한 예로 확인하세요.

작은 연산을 값으로 만들어 두고 필요한 만큼 조합하는 방식이 이론 노트 "고차 함수와 모듈성"의 핵심입니다. 새 요구가 생겨도 기존 함수를 고치지 않고 조합만 바꾸면 됩니다.
