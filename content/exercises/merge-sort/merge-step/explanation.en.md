If both lists are already in ascending order, the first element of the result can only be the smaller of the two head elements. Put that element at the front of the result and merge the two remaining lists the same way. Exactly one element moves to the result at each step, so the total cost is proportional to the sum of the two lengths.

Matching both lists together with `case left, right` splits the work cleanly into four cases. If the left is empty, return the right **as it is**; if the right is empty, return the left as it is. The remaining side is already sorted, and because lists are immutable it is shared as the tail without copying (`cost-model-immutable-structures`). If both have elements, the `x <= y` guard takes the smaller-or-equal one first.

There are two common mistakes. Returning `[]` when one side is empty makes the elements left on the other side disappear. Splitting the comparison only into `<` and `>`, and on equality adding just one element while advancing both sides, loses duplicate values. The rule of taking **the left one first** on equal values is later what guarantees the sort is stable (equal keys keep their original order). This merge is the "combine" step of divide and conquer (`divide-and-conquer`).
