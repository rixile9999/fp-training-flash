작은따옴표는 두 가지 역할을 합니다. `don't`의 작은따옴표는 단어의 일부이고, `'large'`의 작은따옴표는 인용 부호입니다. 글자만 봐서는 구별할 수 없지만 **위치**로는 구별됩니다. 단어 가운데 있으면 축약형, 조각의 맨 앞이나 맨 뒤에 있으면 인용 부호입니다.

그래서 처리를 두 단계로 나눕니다.

1. `tokens`: 작은따옴표를 단어 글자로 취급하고 나머지 구분자로만 나눕니다. 이 단계에서는 `'can't'`가 한 조각으로 남습니다.
2. `trim_quotes`: 조각 앞뒤의 작은따옴표만 떼어 냅니다.

```gleam
token
|> string.to_graphemes
|> list.drop_while(fn(g) { g == "'" })   // 앞쪽 따옴표 제거
|> list.reverse
|> list.drop_while(fn(g) { g == "'" })   // 뒤쪽 따옴표 제거
|> list.reverse
|> string.concat
```

`'` 하나나 `''`처럼 따옴표만 있던 조각은 정리 후 빈 문자열이 되므로, 세기 전에 한 번 더 걸러야 합니다. 흔한 실수는 두 가지입니다.

- 작은따옴표를 처음부터 구분자로 취급해 `don't`가 `don`과 `t`로 쪼개지는 것.
- 앞뒤 따옴표를 떼지 않아 `'large'`와 `large`가 다른 단어로 세어지는 것.

문제를 "나누기"와 "조각 정리"라는 독립된 작은 함수로 나누면 각각을 따로 테스트할 수 있고, `count_words`는 이들을 잇는 파이프라인이 됩니다. 이 합성 방식은 이론 노트 function-composition-pipelines(함수 합성과 파이프라인)에서, 마지막 세기 단계는 fold-universality(fold의 보편성)에서 다룹니다.
