네 함수는 한 줄로 쌓입니다. `clean_word`가 단어 하나의 규칙을, `to_words`가 문장 전체의 규칙을 맡고, `slugify`와 `short_slug`는 `to_words`의 결과를 어떻게 이을지만 정합니다.

```gleam
text
|> string.split(" ")
|> list.map(clean_word)
|> list.filter(fn(word) { word != "" })
```

이 문제의 함정은 **거르기의 위치**입니다. `"-"`나 `"&"` 같은 조각은 나눈 직후에는 비어 있지 않다가, `clean_word`를 거친 뒤에야 빈 문자열이 됩니다. 그래서 빈 단어를 버리는 `list.filter`는 반드시 정리 **뒤에** 와야 합니다. 앞에 두면 `"fresh-apples-5kg--sale"`처럼 하이픈이 겹칩니다. 뒤에 두면 연속 공백 때문에 생긴 빈 조각도 같은 필터가 함께 처리하므로 규칙이 하나로 끝납니다.

`short_slug`도 같은 이유로 `to_words`를 재사용해야 합니다. 원문을 나눈 직후 `list.take`로 자르면 기호뿐인 조각도 한 단어로 세어져 단어 수가 모자랍니다. "정리된 단어" 목록에서 고르는 것이 요구 사항이므로, 이미 정리를 끝낸 `to_words`의 결과를 받아 `list.take`만 하면 됩니다. `list.take`는 개수가 0 이하이면 빈 목록을, 목록보다 크면 전체를 돌려주므로 경계 처리가 따로 필요 없습니다.

같은 단계 함수라도 합성 순서가 바뀌면 다른 함수가 됩니다. 이론 노트 "함수 합성과 파이프라인"을 참고하세요.
