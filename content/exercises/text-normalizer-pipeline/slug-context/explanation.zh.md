这四个函数层层叠成一条线。`clean_word` 负责单个单词的规则，`to_words` 负责整个句子的规则，`slugify` 和 `short_slug` 只决定如何连接 `to_words` 的结果。

```gleam
text
|> string.split(" ")
|> list.map(clean_word)
|> list.filter(fn(word) { word != "" })
```

这道题的陷阱在于**过滤的位置**。`"-"` 或 `"&"` 这样的片段在刚拆分时并不为空，经过 `clean_word` 之后才变成空字符串。所以丢掉空词的 `list.filter` 必须放在整理**之后**。放在前面，连字符就会重叠，比如 `"fresh-apples-5kg--sale"`。放在后面，连续空格产生的空片段也由同一个过滤器一并处理，一条规则就够了。

出于同样的原因，`short_slug` 也必须复用 `to_words`。如果在拆分原文后立即用 `list.take` 截取，只有符号的片段也会被算作一个单词，单词数就不够了。需求是从“整理好的单词”列表中选取，所以只要拿已经整理完毕的 `to_words` 结果做 `list.take` 即可。`list.take` 在数量小于等于 0 时返回空列表，大于列表长度时返回整个列表，因此不需要另外处理边界。

即使是同样的步骤函数，组合顺序一变就成了不同的函数。请参考理论笔记“函数组合与管道”。
