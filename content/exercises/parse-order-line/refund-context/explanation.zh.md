结构和解析一行订单相同。拆分字段，用 `case` 模式检查个数，再用 `use` 和 `result.try` 串联为每个字段返回 `Result` 的函数。前一步失败时后面的步骤不会执行，所以检查顺序和代码顺序一致（**串联 Result 与单子（chaining-results-monads）** 主题）。

本题新增的有两点。

- **把字符串转换成自定义类型。** `parse_reason` 把已知的字符串对应到构造器，其余的交给 `UnknownReason`。像这样在边界处转换一次，之后的代码只需处理 `Reason` 的三种情况，漏掉的情况编译器会告诉你（**和类型与穷尽匹配** 主题）。比较时用 `string.lowercase` 后的值，但错误中放入原始字段，原样展示用户输入的内容。
- **两端都有边界的范围。** 像 `Ok(amount) if amount >= 1 && amount <= max_amount` 这样把两个条件都写在一个守卫里。上限是“小于等于”，所以 1,000,000 是允许的。

常见错误：

- 区分大小写比较原因，拒绝了 `"Wrong_Item"`。
- 把上限写成 `<`，拒绝了正好 1,000,000 的申请（边界值差一）。
- 只检查下限，忘了上限。
