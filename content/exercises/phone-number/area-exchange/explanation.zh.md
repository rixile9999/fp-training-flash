两个检查函数的形状都是 `fn(String) -> Result(String, PhoneError)`。通过时原样返回收到的号码，失败时返回带有原因的错误。形状相同，所以可以用 `result.try` 一个接一个地串起来。

```gleam
pub fn clean(input: String) -> Result(String, PhoneError) {
  normalize(input)
  |> result.try(check_area_code)
  |> result.try(check_exchange_code)
}
```

管道的顺序就是规格的顺序。前面的步骤产生 `Error` 时，后面的步骤不会执行，该错误原样输出。以后再添加一项检查，也只需加一行。

每个检查函数都假定收到的是“整理好的 10 位号码”。有了这个假定，函数内部就不必操心分隔符或国家代码，只要用 `string.slice(number, 0, 1)`、`string.slice(number, 3, 1)` 看想看的那位数字即可。保证这个假定成立是 `clean` 的责任：必须先经过 `normalize`。

常见错误有四种。

- 只拦截示例中出现的数字。规则是“第一位数字是 `2`–`9`”，所以两种代码都必须同时拦截 `0` 和 `1`。以允许的范围为基准来思考，就不会遗漏。
- 弄错交换码的位置。交换码是第四位数字，从 0 开始数是位置 3。
- 先对原始输入做检查，之后才整理。`"1 (223) 456-7890"` 开头的 `1` 是国家代码，却会被误认为区号。像 `"023"` 这样的短输入，也会得到区号错误而不是长度错误。
- 调换两项检查的顺序。两者都错的号码会报告出不同的错误。

把形状相同、可能失败的步骤串起来的方式，在理论笔记“串联 Result 与单子”（chaining-results-monads）中有更多讨论。
