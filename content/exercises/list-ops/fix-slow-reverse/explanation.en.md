The original `reverse` translates the definition "reverse the rest and put the first element at the very end" directly, so the result is correct. The problem is the cost. `append(first, second)` copies all of `first`, so reversing a list of length k copies a list of length k-1, and inside that, one of length k-2, and so on. Altogether that is 1 + 2 + ... + n, that is O(n^2), and at 200,000 lines it is about 20 billion copies.

On an immutable list, the only cheap operation is prepending, `[x, ..acc]` (`cost-model-immutable-structures`). If you read the list from the front and stack onto the front of an accumulator, the elements read first get pushed further and further back, so once you have read everything the order is exactly reversed. The `foldl` already in the module is exactly the function that "reads from the front while accumulating", so the single line `foldl(over: list, from: [], with: fn(acc, x) { [x, ..acc] })` makes it O(n) (`accumulators-and-tail-recursion`).

There are two common half-fixes. Switching to `foldl` but appending with `append(acc, [x])` does not even reverse the order and is still O(n^2). Writing your own accumulator loop but returning `[]` instead of `acc` at the end throws away the collected result. In the accumulator pattern, the base case is "when you reach the end, return the accumulator".
