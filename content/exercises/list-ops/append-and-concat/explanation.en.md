`append(first, second)` rebuilds the elements of `first` one by one from the front and, at the very end, uses `second` **as the tail as is**. Because lists are immutable, `second` is shared and never needs to be copied. So the cost is proportional only to the length of `first` (`cost-model-immutable-structures`).

Once you know this cost model, the direction of `concat` follows. If you accumulate from the front with `append(acc, list)`, `acc` keeps getting longer, and every time you join one more list you copy everything joined so far again. With k small lists the amount of copying is proportional to 1 + 2 + ... + k, that is O(k^2), and with 100,000 lists it exceeds the time limit. If instead you join **from the back**, as in `append(list, concat(rest))`, each inner list is copied exactly once and the rest is shared, so the cost is proportional to the total number of elements. This shape is the same as folding `append` with `foldr` (`fold-universality`).

Another common mistake is to make it tail recursive by moving the elements of `first` one by one to the front of `second`, as in `append(rest, [x, ..second])`. Then the `first` part is reversed, and `[1, 2] + [3]` becomes `[2, 1, 3]`. If you really need tail recursion, reverse `first` first and then move the elements.
