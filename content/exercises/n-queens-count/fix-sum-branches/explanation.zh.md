`place` 表示“从这一行填到最后的方法数”，所以对这一行可选的每个安全的列，都要把下面各行的统计结果**加起来**。原代码丢掉了 `int.range` 的累加值 `total`，只返回刚统计的那一列的结果。于是只剩下从最后一个安全列出发的摆法数。在 4x4 棋盘上，从第一行第 3 列出发没有摆法，所以得到 0。

当搜索树中一个节点的答案是把子节点的答案合并起来时，漏掉合并运算（这里是加法），就只会反映树的一条分支（`search-space-backtracking`）。改成 `total + place(n, row + 1, [col, ..placed])`，所有分支就都合并起来了。

常见的错误修复有两种。把基本情况改成 `row == n - 1`，会把没有填最后一行的摆法也算进去，答案变大。修好了求和却没有把新皇后加入 `placed`，下面各行检查时就不知道有这个新皇后，从而把互相攻击的摆法也算进去。
