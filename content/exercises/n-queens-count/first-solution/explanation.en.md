If you try the columns of each row in order from column 0 and stop searching the moment every row is filled, the first placement you find is the lexicographically first one. That is because you examine all the placements with a small first-row column before the others, and within those, the ones with a small second-row column first.

"Find the first solution" is naturally expressed as a recursion that returns a `Result`. If the search of the rows below gives `Ok`, pass it straight up; if it gives `Error(Nil)`, move on to the next column of this row. If every column fails, this row also returns `Error(Nil)`, which makes the row above try its next column. That is going back, or backtracking (`search-space-backtracking`). On a 6x6 board, placing 0 in the first row can never be completed, so after backtracking several times the search finds the answer with 1 in the first row. A greedy solution that picks the first safe column and never goes back happens to work on 5x5, but fails on 4x4 and 6x6.

New queens are prepended to `placed`, so the lowest row is at the front. The result must start from the top row, so you reverse it once at the end. Without the reverse, 4x4 gives `[2, 0, 3, 1]`, which is also a valid placement, so the order problem is easy to miss. If you try the columns from the largest first, you find the lexicographically last placement instead.
