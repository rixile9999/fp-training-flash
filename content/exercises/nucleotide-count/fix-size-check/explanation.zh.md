原来的代码有两个 bug。

1. 它从 `dict.new()` 开始，只统计出现过的字母，所以没出现的碱基的键不在结果中。
2. 它用“种类是否不超过 4 个”来间接判断有效性。`"AAX"` 只有 2 种（`A` 和 `X`），于是蒙混过关。大小代替不了规则。

修改后的代码从四种碱基都为 0 的字典开始，用 `list.try_fold` 逐个统计字母。如果 `dict.get(counts, letter)` 失败，说明这个字母不是四种碱基之一，于是立即以 `Error(Nil)` 停止。一个初始值同时决定了“结果中有哪些键”和“哪些字母有效”，两个 bug 一次就都消失了。

常见的半截修复是只改其中一个。即使最后用 `dict.merge` 补上 0，只要大小检查还在，`"AAX"` 仍会通过；即使改成逐个字母检查，只要还从空字典开始，数量为 0 的键仍会缺失。

与其在整个结果建好之后去推测它的性质，不如在折叠过程中直接表达规则，这样更准确（理论笔记“fold 的普适性：列表递归的共同骨架”）。失败用 `Result` 报告（理论笔记“错误也是值”）。
