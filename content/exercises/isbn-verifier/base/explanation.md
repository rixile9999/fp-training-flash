`is_valid`는 어떤 문자열에도 답해야 하는 **전체 함수**입니다. 그런데 그 안의 "글자를 숫자로 바꾸기"는 실패할 수 있는 부분 연산입니다. 해법은 실패할 수 있는 부분을 `Result`로 받아서 처리하고, 가장 바깥에서 한 번만 `Bool`로 바꾸는 것입니다.

코드는 두 단계로 나뉩니다.

- **파싱** `parse(isbn) -> Result(List(Int), Nil)`: 하이픈을 지우고, 길이가 10인지 보고, 글자마다 값을 구합니다. `char_value`는 위치 9의 `X`만 10으로 인정하고 나머지는 `int.parse`에 맡깁니다. `list.try_map`이 첫 실패에서 `Error(Nil)`을 돌려주므로, 잘못된 글자가 하나라도 있으면 파싱 전체가 실패합니다.
- **계산** `checksum(values)`: 값 목록만 받아 가중합을 구합니다. 여기서는 입력이 이미 올바르다고 믿어도 됩니다.

```gleam
case parse(isbn) {
  Ok(values) -> checksum(values) % 11 == 0
  Error(Nil) -> False
}
```

흔한 실수는 세 가지입니다.

- 파싱에 실패한 글자를 `result.unwrap(int.parse(char), 0)`처럼 0으로 바꾸는 것. 멈추지는 않지만 `3-598-P1581-X`처럼 우연히 가중합이 맞는 잘못된 입력을 `True`로 판정합니다. 실패를 기본값으로 덮으면 "전체 함수"가 아니라 "틀린 답을 내는 함수"가 됩니다.
- `X`를 위치와 상관없이 10으로 받는 것. `X`는 검사 숫자 자리에서만 의미가 있습니다.
- 길이 검사를 빠뜨리는 것. 빈 문자열은 가중합이 0이라 11로 나누어떨어지므로 `True`가 나옵니다.

`let assert Ok(d) = int.parse(char)`처럼 쓰면 잘못된 글자에서 프로그램이 멈춥니다. 실패 가능성을 타입으로 드러내고 끝까지 처리하는 이유는 이론 노트 "전체 함수와 부분 함수"(total-vs-partial-functions)에서 더 다룹니다.
