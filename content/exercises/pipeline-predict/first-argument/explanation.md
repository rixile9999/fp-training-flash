정답은 `14`입니다.

Gleam의 파이프 `a |> f(b)`는 `f(a, b)`로 바뀝니다. 왼쪽 값이 오른쪽 함수의 **첫 번째 인자**로 들어갑니다. 그래서 위 코드는 다음과 같습니다.

```gleam
int.multiply(int.subtract(10, 3), 2)
// int.subtract(10, 3) = 10 - 3 = 7
// int.multiply(7, 2)  = 14
```

흔한 실수는 파이프 값이 마지막 인자로 들어간다고 생각해 `int.subtract(3, 10) = -7`로 계산하는 것입니다(답 -14). 다른 언어의 파이프나 커링 습관 때문에 생기는 착각입니다. Gleam 표준 라이브러리 함수는 대부분 "주로 다루는 값"을 첫 인자로 두므로 `list |> list.map(f)`처럼 자연스럽게 이어집니다. 첫 인자가 아닌 자리에 넣고 싶을 때는 `int.subtract(100, _)`처럼 `_`로 자리를 표시합니다(이론 주제 "함수 합성과 파이프라인").
