把进制转换拆成“数字位列表 → 整数 → 数字位列表”两步，问题就变简单了。第一步从左往右累加 `total * base + digit` 得到数值；第二步用输出进制去除这个值并收集余数，就得到新的数字位。

只有第一步可能失败，所以错误也只在那里产生。`list.try_fold` 在累加过程中一遇到 `Error` 就立即停止，因此自然会报告“最前面的错误数字位”。返回类型 `Result(List(Int), RebaseError)` 暴露了失败的可能性，调用方就无法忽视错误的输入。这正是理论笔记“错误也是值”（errors-as-values）的核心。而且它对任何输入都不会崩溃，总是返回 `Ok` 或 `Error`，所以是一个全函数（理论笔记“全函数与偏函数”，total-vs-partial-functions）。

先用 `case input_base < 2, output_base < 2` 完成进制检查也很重要。输出进制为 1 时，`value / 1` 不会变小，第二步永远不会结束；为 0 时，Gleam 的整数除法返回 0，会得到莫名其妙的数字位。规定检查顺序则是出于另一个原因：即使多个错误同时出现，也必须唯一确定报告哪一个，这样同样的输入才总能得到同样的结果。

常见错误有两种。

- 值为 0 时，“一直除到 0 为止”的循环一次也不执行，于是返回 `[]`。题解先加上余数，再用 `value < base` 判断是否停止，所以 0 也会变成 `[0]`。
- 漏掉数字位检查，只用 `fold` 计算。`[1, 2]`（二进制）会悄悄变成 4，错误的答案看起来像正确答案。
