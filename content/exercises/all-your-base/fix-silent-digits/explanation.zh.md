原来的代码先用 `list.filter` 滤掉错误的数字位，再进行计算。类型上承诺的是 `Result`，实际上对错误的输入也返回 `Ok`，于是调用方会把错误的值当成正确答案。这种 bug 比程序崩溃更难发现。

修改后的代码把“检查”和“累加”合并成一个 `list.try_fold`。对每个数字位检查范围：合法就用 `Ok(total * base + digit)` 继续，不合法就用 `Error(InvalidDigit(digit))` 立即停止。只有成功时才用 `result.map` 接上到输出进制的转换，所以失败会原样传递到最后。正如理论笔记“错误也是值”（errors-as-values）所说，只有把失败放进返回值，调用方才能处理这个失败。

常见错误如下。

- 把错误的数字位换成 0 或直接滤掉。“修好”输入再继续，只不过是隐藏失败的另一种方式。
- 用 `list.fold` 把累加器本身当作 `Result` 带着走，并不断覆盖错误。这样报告的是最后一个错误，而且第一个错误之后计算仍在继续。
- 只检查 `digit < base`，漏掉了负数。
