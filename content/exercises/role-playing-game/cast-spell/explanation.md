규칙이 마나의 세 가지 상태에 따라 나뉘므로, `player.mana` 하나로 `case`를 만들고 가지를 셋 두면 규칙과 코드가 그대로 대응합니다.

```gleam
case player.mana {
  Some(mana) if mana >= cost -> ...  // 시전 성공
  Some(_) -> #(player, 0)             // 마나 부족
  None -> ...                         // 마나 없음: 체력으로 대가를 치름
}
```

가장 흔한 실수는 `option.unwrap(player.mana, 0)`으로 먼저 값을 꺼내는 것입니다. 이렇게 하면 `None`(마나가 아예 없음)과 `Some(0)`(마나가 바닥남)이 같은 0이 되어 버리고, 둘을 다시 구분할 방법이 없습니다. 이 문제에서 둘은 결과가 다릅니다. `Some(0)`은 아무 일도 없고, `None`은 체력이 줄어듭니다. `Option`을 쓰는 이유가 바로 "없음"을 다른 값과 섞이지 않게 하려는 것이므로, 규칙이 다르다면 `case`로 `None`을 따로 다뤄야 합니다.

경계 두 곳도 주의하세요.

- 시전 조건은 `mana >= cost`입니다. `>`로 쓰면 마나를 딱 맞게 가진 경우 시전이 실패합니다.
- 체력은 `int.max(0, player.health - cost)`로 0 아래로 내려가지 않게 합니다.

마나 부족 가지에서 `player`를 그대로 돌려주는 것도 의도된 설계입니다. 불변 값이므로 "변화 없음"은 새 값을 만들지 않고 원래 값을 돌려주는 것으로 표현됩니다.

"없음"을 타입으로 드러내 모든 경우를 다루게 하는 생각은 이론 노트 "합 타입과 빠짐없는 분기"(algebraic-data-types)에서 더 다룹니다.
