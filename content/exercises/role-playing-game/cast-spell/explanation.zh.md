规则按法力值的三种状态划分，所以只对 `player.mana` 做 `case` 并设三个分支，规则和代码就能一一对应。

```gleam
case player.mana {
  Some(mana) if mana >= cost -> ...  // 施法成功
  Some(_) -> #(player, 0)             // 法力值不足
  None -> ...                         // 没有法力值：用生命值付出代价
}
```

最常见的错误是先用 `option.unwrap(player.mana, 0)` 把值取出来。这样 `None`（根本没有法力值）和 `Some(0)`（法力值耗尽）都会变成同一个 0，再也无法区分。在本题中两者的结果不同：`Some(0)` 什么都不发生，`None` 则会减少生命值。使用 `Option` 正是为了不让“没有”和其他值混在一起，所以规则不同时，就要用 `case` 单独处理 `None`。

还要注意两处边界。

- 施法条件是 `mana >= cost`。写成 `>` 的话，法力值刚好够用时施法会失败。
- 用 `int.max(0, player.health - cost)` 让生命值不降到 0 以下。

在法力值不足的分支里原样返回 `player` 也是有意的设计。它是不可变的值，所以“没有变化”就用返回原值、而不是构造新值来表达。

用类型体现“没有”、从而迫使所有情况都得到处理，这一思路在理论笔记“和类型与穷尽匹配”（algebraic-data-types）中有更多讨论。
