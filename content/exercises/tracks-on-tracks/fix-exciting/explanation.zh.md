原来的代码有两处 bug。

1. `[_] -> False`：把只有一个元素的列表一律判为 False。`["Gleam"]` 的第一个是 Gleam，应该为 True。
2. `list.length(languages) >= 2`：进入 `[first, second, ..]` 分支的列表长度已经不小于 2，所以这个条件永远为真。真正需要的条件是“长度不超过 3”。

如果用数字比较来修正长度条件，很容易在 `<= 3` 和 `< 3` 之间差一位。把结果为真的形状原样写成模式，就不会出现这种边界错误。

```gleam
case languages {
  ["Gleam", ..] -> True
  [_, "Gleam"] | [_, "Gleam", _] -> True
  _ -> False
}
```

`[_, "Gleam"]` 只匹配长度为 2 的列表，`[_, "Gleam", _]` 只匹配长度为 3 的列表。空列表和其他长度为 1 的列表都会进入最后的 `_`。按形状穷尽地划分列表的思路，在理论笔记“和类型与穷尽匹配”中有介绍。
