원래 코드의 버그는 두 곳입니다.

1. `[_] -> False`: 원소가 하나뿐인 목록을 무조건 False로 보냈습니다. `["Gleam"]`은 첫 번째가 Gleam이므로 True여야 합니다.
2. `list.length(languages) >= 2`: `[first, second, ..]` 분기에 들어온 목록은 이미 길이가 2 이상이라 이 조건은 항상 참입니다. 필요한 조건은 "길이가 3 이하"였습니다.

길이 조건을 숫자 비교로 고치면 `<= 3`과 `< 3` 사이에서 한 칸 어긋나기 쉽습니다. 참이 되는 모양을 패턴으로 그대로 적으면 이런 경계 실수가 생기지 않습니다.

```gleam
case languages {
  ["Gleam", ..] -> True
  [_, "Gleam"] | [_, "Gleam", _] -> True
  _ -> False
}
```

`[_, "Gleam"]`은 길이 2, `[_, "Gleam", _]`은 길이 3인 목록에만 맞습니다. 빈 목록과 길이 1인 다른 목록은 마지막 `_`로 갑니다. 목록을 모양별로 빠짐없이 나누는 생각은 이론 노트 「합 타입과 빠짐없는 분기」에서 다룹니다.
