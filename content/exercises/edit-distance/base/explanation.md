`from`의 마지막 글자를 `to`의 마지막 글자에 맞추는 방법은 세 가지뿐입니다. 마지막 글자를 지우거나(삭제), `to`의 마지막 글자를 새로 넣거나(삽입), 바꾸거나(같으면 비용 0) 입니다. 어느 쪽을 택하든 남는 문제는 "더 짧은 앞부분끼리의 거리"입니다. 그래서 d(i, j) = "앞 i글자를 앞 j글자로 바꾸는 최소 횟수"로 두면

d(i, j) = min(d(i-1, j) + 1, d(i, j-1) + 1, d(i-1, j-1) + (같으면 0, 다르면 1))

이고, 빈 문자열이 끼면 d(0, j) = j, d(i, 0) = i입니다(`dynamic-programming-subproblems`).

이 식을 재귀로 그대로 쓰면 답은 맞지만 같은 (i, j)를 여러 경로에서 반복 계산합니다. 글자가 하나 늘 때마다 호출 수가 몇 배씩 늘어서 300글자는 끝나지 않습니다. 서로 다른 (i, j)는 (n+1) x (m+1)개뿐이므로 표로 한 번씩만 계산하면 O(n x m)입니다.

해답은 표 전체 대신 **행 하나씩** 만듭니다. i행은 (i-1)행만 있으면 계산되므로, 첫 행 `[0, 1, ..., m]`에서 시작해 `from`의 글자마다 다음 행을 만드는 `fold`가 됩니다. `fill`은 윗행을 앞에서부터 두 칸씩(대각선, 위) 보면서 왼쪽 값과 함께 새 칸을 계산하고, 결과를 누적자 앞에 쌓은 뒤 한 번 뒤집습니다. 불변 목록의 앞에서만 읽고 앞에만 붙이므로 칸마다 O(1)입니다(`cost-model-immutable-structures`).

흔한 실수는 세 가지입니다. 첫 행을 모두 0으로 두면 "빈 문자열에서 만들기"의 비용이 사라집니다. 바꾸기를 빼먹고 삭제 + 삽입만 쓰면 다른 글자 하나에 2를 셉니다. 그리고 `string.byte_size`처럼 바이트로 세면 한글 한 글자가 3이 됩니다. `string.to_graphemes`로 나누면 글자 단위가 됩니다.
