让 `from` 的最后一个字符与 `to` 的最后一个字符对上，只有三种方法：删掉最后一个字符（删除）、新加入 `to` 的最后一个字符（插入）、或者替换（相同则代价为 0）。无论选哪一种，剩下的都是“更短的前缀之间的距离”。所以令 d(i, j) =“把前 i 个字符变成前 j 个字符的最少次数”，则

d(i, j) = min(d(i-1, j) + 1, d(i, j-1) + 1, d(i-1, j-1) + (相同为 0，不同为 1))

当涉及空字符串时，d(0, j) = j，d(i, 0) = i（`dynamic-programming-subproblems`）。

如果把这个式子原样写成递归，答案是对的，但同一个 (i, j) 会沿着多条路径被重复计算。每多一个字符，调用次数就成倍增长，300 个字符根本算不完。不同的 (i, j) 只有 (n+1) x (m+1) 个，用表让每个只算一次，就是 O(n x m)。

题解不建整张表，而是**一次只建一行**。第 i 行只需第 (i-1) 行就能算出，所以这就成了一个 `fold`：从第一行 `[0, 1, ..., m]` 出发，对 `from` 的每个字符生成下一行。`fill` 从前往后每次看上一行的两格（对角线、上方），结合左边的值算出新的一格，把结果堆在累加器前面，最后反转一次。它只从不可变列表的头部读取、只往头部添加，所以每格是 O(1)（`cost-model-immutable-structures`）。

常见错误有三个。把第一行全设为 0，“从空字符串构造”的代价就消失了。漏掉替换、只用删除 + 插入，一个不同的字符就会算成 2。还有像 `string.byte_size` 那样按字节计数，一个韩文字符会变成 3。用 `string.to_graphemes` 拆分，才是按字符计数。
