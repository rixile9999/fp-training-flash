트리를 만드는 `to_tree`는 맞고, 트리를 목록으로 펼치는 순서가 문제입니다. 원래 `walk`는 자기 값을 먼저 두고 왼쪽, 오른쪽을 잇는 **전위 순회**라서 `[2, 1, 3]`으로 만든 트리(루트 2, 왼쪽 1, 오른쪽 3)를 `[2, 1, 3]`으로 펼칩니다.

이진 탐색 트리의 불변식은 "왼쪽 서브트리의 값 ≤ 노드 값 < 오른쪽 서브트리의 값"입니다. 그러므로 왼쪽을 모두 나열하고, 자기 값을 두고, 오른쪽을 나열하는 **중위 순회**가 곧 오름차순입니다. 각 서브트리도 같은 성질을 가지므로 재귀적으로 정렬된 조각들을 이 순서로 이어 붙이면 전체가 정렬됩니다. 작은 트리에서 성립하는 성질이 더 큰 트리로 그대로 올라가는 구조적 귀납입니다(`structural-recursion-induction`).

흔한 헛수정은 자기 값을 맨 뒤로 옮기는 것(후위 순회)과 오른쪽부터 방문하는 것(내림차순)입니다. 세 원소짜리 트리를 직접 그려서 방문 순서를 확인하면 어느 순서가 맞는지 바로 보입니다.

`list.flatten`으로 이어 붙이는 방식은 읽기 쉽지만, 한쪽으로 치우친 트리에서는 복사가 쌓입니다. 더 효율적인 방식은 오른쪽부터 펼쳐 누적자 앞에 붙이는 것입니다(`accumulators-and-tail-recursion`).
