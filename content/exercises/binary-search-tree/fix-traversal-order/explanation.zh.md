构建树的 `to_tree` 是对的，问题出在把树展开成列表的顺序上。原来的 `walk` 先放自身的值，再拼接左边和右边，这是**前序遍历**，所以由 `[2, 1, 3]` 建成的树（根 2，左 1，右 3）会被展开成 `[2, 1, 3]`。

二叉搜索树的不变式是“左子树的值 ≤ 节点值 < 右子树的值”。因此，先列出左边全部的值、再放自身的值、最后列出右边的**中序遍历**，正好就是升序。每棵子树也具有同样的性质，所以把递归排好序的各段按这个顺序拼接起来，整体就是有序的。这就是结构归纳：在较小的树上成立的性质原样传递到更大的树上（`structural-recursion-induction`）。

常见的无效修改是把自身的值挪到最后（后序遍历），或者先访问右边（降序）。亲手画一棵三个元素的树、检查访问顺序，马上就能看出哪种顺序是对的。

用 `list.flatten` 拼接的写法容易读懂，但在偏向一侧的树上，复制会不断累积。更高效的做法是先展开右边，再往累加器前面添加（`accumulators-and-tail-recursion`）。
