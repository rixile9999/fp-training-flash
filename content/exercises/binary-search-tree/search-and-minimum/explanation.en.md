A binary search tree promises that "everything on the left is less than or equal, everything on the right is greater". Thanks to this promise, comparing one value means you never have to look at the other half. If the value you want is smaller than the node's value, it can never be in the right subtree, so you go down only to the left. Each comparison takes you down one level, so the cost is the tree's height, which is O(log n) for a balanced tree. With 130,000 nodes, one lookup takes about 17 comparisons.

A common mistake is searching both sides, as in `data == value || contains(left, value) || contains(right, value)`. The result is correct, but it treats the tree like a list, so every lookup of a missing value scans all 130,000 nodes. Over 40,000 lookups that is billions of visits, which exceeds the time limit. The key point is that you only reduce the cost by using the data structure's invariant (`cost-model-immutable-structures`).

`minimum` keeps going left until it meets a node with no left child. The pattern `Node(data, Empty, _)` expresses the stopping condition "there is nothing further left" directly. If you stop after checking only the immediate left child, you miss a minimum deeper in the tree. An empty tree has no minimum, so `Result` makes "nothing" visible in the type. If you returned a default such as 0, you could not tell it apart from a real minimum of 0 (`total-vs-partial-functions`).
