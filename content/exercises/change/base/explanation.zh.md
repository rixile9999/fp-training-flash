先选最大硬币的做法（贪心法）在某些面额组合下会出错。用 `[1, 4, 15, 20, 50]` 凑 23 时，如果先选 20，还需要三枚 1，共 4 枚；而 4 + 4 + 15 只要 3 枚。用 `[4, 5]` 凑 27 时，先选五枚 5 会剩下 2，直接卡住。

正确的出发点是**最优子结构**。从金额 a 的最少组合中拿掉一枚硬币 c，剩下的硬币一定是金额 a - c 的最少组合。所以 a 的答案就是对所有硬币 c 求“1 + (a - c 的答案)”后取最小值（`dynamic-programming-subproblems`）。

把这个式子直接写成递归，答案是对的，但小金额的答案会被反复重算，调用次数随金额呈指数增长。金额是 999 时根本算不完。子问题只有金额 0..target 这 target + 1 个，所以从 0 开始依次计算、存进 `Dict`，需要时取出来用，总开销就是 O(金额 x 硬币种类数)。

参考解在表中存放 `#(硬币枚数, 用到的硬币)`。单独记下枚数，比较候选时就不必再用 `list.length` 重新数；`[coin, ..used]` 也能不复制地共享上一个金额的列表（`cost-model-immutable-structures`）。凑不出的金额不放进表里，`dict.get` 返回的 `Error(Nil)` 自然就表示“不可能”。如果用 0 或很大的数这类特殊值标记，就会和真实的值混在一起，容易出错（`errors-as-values`）。最后把结果按升序排序。表里累积的硬币顺序取决于 `coins` 给出的顺序，只有硬币列表恰好是升序时才会碰巧有序。
