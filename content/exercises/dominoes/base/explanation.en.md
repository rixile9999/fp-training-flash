A chain is a loop, so you can fix the first stone of the chain to be the first stone of the input. The search state then has three parts: the chain's first number (`first`), the number at the current end (`end`), and the stones not used yet (`remaining`). When no stones remain and `end == first`, the loop is complete.

If stones remain, pick one that has the same number as `end` and attach it. If the stone's left number equals `end`, its right number becomes the new end; if its right number equals `end`, flip it and its left number becomes the new end. Depending on which stone you pick, you may get stuck later, so you have to try every candidate. `list.any` stops as soon as one candidate reaches the end, and if all of them fail it returns `False`, so the level above tries another stone. That is backtracking (`search-space-backtracking`).

There are three common mistakes. If you pick only the first matching stone and never go back, the loop can close too early, as in `[1|2] [2|3] [3|1]`, leaving the two remaining `[2|4]` stones unusable. If you leave out flipping, you miss stones that could connect. If you just return `True` when no stones remain without comparing the two ends, even a single `[1|2]` is judged to be a chain.

If you remove a used stone by filtering on its value, as in `list.filter(fn(s) { s != stone })`, every stone of the same shape disappears at once. The provided `selections` builds pairs of each element and "the rest with only that one element removed", so it removes exactly one by position. Because lists are immutable, `remaining` is unchanged when you come back from trying one option, so you need no code to undo anything.
