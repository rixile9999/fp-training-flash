The original `extend` tried only the **first** of the candidates that could attach to the current end. If you choose `[2|3]` after `[1|2]`, `[3|1]` closes the loop right away, and the two remaining `[2|4]` stones have nowhere to go, so the result is `False`. In fact `[2|4]` should have been chosen first. You only find out whether a choice is good by going all the way, so when it fails you must go back and try another candidate.

`next_steps` already builds every candidate, so you only need to try recursing on each one with `list.any`. `list.any` stops as soon as one returns true, and if all of them fail it returns `False`, so the level above tries its next candidate (`search-space-backtracking`).

There are two common half-fixes. Repeating the same greedy search while only changing the starting stone still misses cases like `[1|3] [4|3] [1|4] [1|1] [4|4]`, where the wrong spot is chosen for a double stone (`[1|1]`, `[4|4]`). Backing out is needed at every step, not just at the starting point. Also, if you rewrite `next_steps` and remove the used stone with `list.filter(fn(s) { s != stone })`, every stone of the same shape disappears too. Like `selections` in the original code, you must remove exactly one, by position.
