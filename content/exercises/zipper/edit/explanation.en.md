The focus of a zipper is "the spot you can work on right now". Whether you change the value or a child, build only the focus node anew and leave the path (crumbs) as it is. Later, when you go up with `up` or `to_tree`, the path fits the new focus back into its parent nodes, so the change is reflected in the whole tree. The record update `Zipper(..zipper, focus: ...)` expresses exactly "keep the path, change only the focus".

The only node built anew is the focus, and on the way up the parents along the path are rebuilt one by one. All the other subtrees are shared with the original tree (`immutability-structural-sharing`). That is why the zipper before the change and the zipper after it can both be used at the same time (`persistent-data-structures`).

A common mistake is the handling of a `Leaf` focus. If `set_value` does nothing at a `Leaf`, you cannot put a new value into an empty spot. Conversely, if `set_left`, at a `Leaf`, simply makes the tree it received the new focus, that amounts to changing a child of a node that does not exist, which goes against the rules. Putting the new child on the wrong side in `Node(value, left, right)` is also a frequent mistake. Check the order of the constructor fields (value, left, right).
