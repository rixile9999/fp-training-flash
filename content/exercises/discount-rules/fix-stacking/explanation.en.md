**The bug in `apply_all`: the accumulator is not used.** The original code calls `apply_coupon(price, coupon)` inside the fold. It applies each coupon to the original price and throws away the previous result, so it behaves as if only the last coupon were applied. The compiler warning that "`total` is not used" is the clue. The function in a fold means "build a new result from the result so far (the accumulator) and the next element", so it must be `apply_coupon(total, coupon)`. Then the whole list of coupons behaves like a single discount function composed step by step (theory topic "Function composition and pipelines").

**The bug in `best_single`: the initial value of the minimum fold.** `list.fold(0, int.min)` always returns 0, because 0 wins against any price. The initial value of a fold that finds a minimum must not change the result, and in this problem `price`, "the price without any coupon", fits exactly. It also naturally satisfies the requirement that `price` comes out when there are no coupons.

A common wrong fix is `list.reduce(int.min) |> result.unwrap(0)`. It is right when there are coupons, but an empty list gives a price of 0. If you first decide what the right answer for an empty list is, the initial value of the fold follows. Also, if you change `apply_all` to `list.fold_right`, the coupons are applied from the back, and the result changes depending on the order of fixed-amount and percentage coupons.
