`percent_off` 和 `amount_off` 返回的不是价格，而是**函数**。内部的匿名函数 `fn(price) { ... }` 会记住外层参数 `percent` 或 `amount`，所以 `percent_off(10)` 就成了“减 10% 的规则”这样一个值。规则一旦成为值，就可以放进列表、调整顺序、传给其他函数。即使出现新的折扣类型，也不需要修改 `apply_rules`（理论主题“高阶函数与模块化”）。

`apply_rules` 用 `list.fold` 把“到目前为止的折后价格”作为累加器带在身上，逐条应用规则。初始值是原价，所以没有规则时价格原样返回。对规则列表做 fold，等同于把这些规则组合成一个函数（理论主题“函数组合与管道”）。

常见错误如下：

- 使用 `list.fold_right` 时，规则会从后往前应用。百分比折扣和固定金额折扣的顺序不同，结果也不同（8000 对 8100），所以顺序是需求的一部分。
- 固定金额折扣如果不设下限，就会出现负数价格。像 `int.max(price - amount, 0)` 这样在规则内部守住不变条件，无论以什么顺序组合，价格都不会变成负数。
