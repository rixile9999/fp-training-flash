In the original code, `steps` is the **number of cells taken out** of the queue. In a straight corridor every cell taken out lies on the route, so it happens to equal the answer, but when there are branches, cells off the route are also taken out and `steps` keeps growing. The number of moves is not a single counter for the whole search; it is a different value **for each cell**.

So put each position in the queue together with its distance, as `#(position, distance)`. Neighbors are put in with the distance of the cell taken out + 1, and when G is taken out, return the distance stored in that entry. Breadth-first search takes cells out in order of distance, so the distance of the first G taken out is the shortest. In recursion that passes state as arguments, first decide "what is a value of the whole search and what is a value of each cell" (`search-space-backtracking`).

There are two common mistakes while fixing it. If you attach `dist` to the neighbors instead of `dist + 1`, every cell gets distance 0. If you prepend the neighbors to `front` instead of `back`, the queue becomes a stack and the search becomes depth-first, so in a large room it returns the distance of a long detour. Keep the order of the two-list queue as it is and only attach the distance to each cell.
